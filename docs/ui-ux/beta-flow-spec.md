# 首轮 Beta UI/UX 流程规格

> 状态：可交付给前端实现与测试
>
> 范围：单猫 Momo、背单词、免费基础互动、温和提醒/休养/重逢
> 非范围：犬类、多宠物、阅读、口语、商城、真实收款、排行榜、动态视频

## 1. 体验目标与边界

首轮 Beta 要验证“短时英语学习是否能形成可持续、低压力的陪伴循环”，而不是验证用户能否被宠物规则催促回来。

- 宠物是用户成长的伙伴，不是惩罚或付费转化工具。
- 学习完成、积分、陪伴状态、时间阈值与重逢结果均以服务端响应为准；客户端只显示状态和提交操作。
- 喂食、补水、整理与重逢都是免费基础互动，不消耗积分、库存或权益。
- 用户离开不会失去宠物、亲密度、共同记忆或已解锁内容。休养只暂停新的成长反馈。
- 任何页面都不显示商城、积分兑换、动态视频、狗狗预览或未开放学习任务的可执行入口。

## 2. Beta 信息架构

```text
首次使用
欢迎与安心说明 → 登录 → 命名并领养 Momo → 今日

主导航
今日 ─ 学习 ─ Momo ─ 我的
```

| 页面       | 用户目标                 | 必须内容                                                              | 主要操作                           |
| ---------- | ------------------------ | --------------------------------------------------------------------- | ---------------------------------- |
| 欢迎与领养 | 明白规则并建立第一段关系 | “离开不会失去 Momo”、基础互动免费、自然陪伴声可关闭、昵称输入         | 登录、确认领养                     |
| 今日       | 知道当下最有价值的下一步 | Momo 场景、权威陪伴状态、今日学习 `x/3`、可用积分、最近共同记忆       | 开始背词；提醒/休养时改为去陪 Momo |
| 学习       | 完成一组可验证的背词     | 剩余额度、预计时长、10 题过程、作答反馈、结果与回执                   | 开始/继续学习、查看错词、返回今日  |
| Momo       | 轻量互动并理解状态       | 当前状态、上次互动、任选一项免费互动、状态时间线、休养时的重逢卡      | 互动或免费重逢                     |
| 我的       | 查看记录与控制体验       | 积分账本、学习记录、连续学习、提醒偏好、声音、减少动态效果、隐私/账户 | 调整偏好、查看记录                 |
| 研究反馈   | 验证假设，不干扰核心使用 | 可跳过的陪伴感、提醒压力、内容偏好/价格区间问题                       | 提交或跳过                         |

“研究反馈”不是主导航页。它只能在学习结果页、首次重逢后或第 7/14 天以可跳过卡片出现；不展示购买按钮、不扣积分、不承诺未开发内容。

## 3. 核心流程

### 3.1 首次领养

1. 欢迎页先展示三条可理解的承诺：宠物不会因离开消失、基础互动始终免费、自然陪伴声可随时关闭。
2. 用户登录后填写 Momo 的名字；名称输入需有长度提示、示例和可读的校验错误。
3. 点击“领养 Momo”后，按钮进入提交中状态；成功后显示领养时间和“从今天起一起学习”的确认页。
4. 进入今日页时，积分、连续学习、共同记忆均为真实初始空状态；不得用演示账户的 68 积分或历史记录充当真实数据。

### 3.2 背词 → 权威回执 → 陪伴反馈

```text
今日/学习页开始背词
→ 第 1–10 题（显示题号和本组进度）
→ 每题即时正确/错误反馈与简短解释
→ 结果页（正确数、错词、是否达到 8/10）
→ 服务端确认中
→ 权威回执
→ 一次与结果一致的 Momo 反馈
→ 返回今日
```

- 每题选项提交后须禁用本题再次作答，保留正确答案和解释，再由用户主动进入下一题。
- 得分达到 `8/10` 时才显示“本组完成，获得 8 分”；未达到时显示“这组先记为练习，看看错词后再试一次”，不播放得分或庆祝动画。
- 结果页显示服务端确认中、已确认、查询上次结果、可重试四种状态。网络中断不得让用户重新答题来换取重复奖励。
- 今日学习进度按每日三组计算，展示为 `0/3`、`1/3`、`2/3`、`3/3`，对应进度为 0%、33%、67%、100%。

### 3.3 免费陪伴

1. Momo 页将喂食、补水、整理呈现为“今天想怎么陪伴？任选一项”，而非三项待办。
2. 用户选择任一互动后，按钮进入提交中；服务端确认后显示一次短互动反馈，并在时间线增加事件。
3. 已完成的互动显示“已完成”，但其他互动仍可作为可选表达保留，不能暗示用户必须全部完成。
4. 今日页更新为最新的权威陪伴状态和一条共同记忆。

### 3.4 温和提醒 → 休养 → 重逢

| 服务端状态键 | 展示名   | 触发条件               | 页面文案与视觉                                                          | 主操作       | 不得出现                   |
| ------------ | -------- | ---------------------- | ----------------------------------------------------------------------- | ------------ | -------------------------- |
| `normal`     | 正常陪伴 | 最近一次基础互动仍有效 | “Momo 正在安静陪伴”；自然光场景与最近互动                               | 开始今日学习 | 待办压力、倒计时           |
| `reminder`   | 温和提醒 | 36 小时未完成基础互动  | “距离上次互动约 X 小时；有空回来打个招呼”；文字、图标和关闭入口同时出现 | 去陪 Momo    | 责备、宠物痛苦暗示         |
| `resting`    | 休养     | 72 小时未完成基础互动  | “Momo 在安全的休养空间等你；记忆和关系都在”；显示最后互动时间           | 免费重逢     | 受伤、死亡、损失、付费恢复 |

- `reminder` 可关闭；关闭只控制展示/通知偏好，不改变服务端状态。
- `resting` 必须有独立安全空间和独立的重逢卡，不能只用“安静陪伴”的普通图片代替。
- 重逢成功后，先展示“欢迎回来”与保留的共同记忆，再提供“开始一组背词”作为次级、可跳过建议。
- 重逢是一次服务端可审计事件，不是服务端状态。点击“免费重逢”后，客户端可短暂显示 `reunion_pending`（正在提交）界面；收到服务端结果后必须刷新为 `normal` 或显示可重试错误，不能保留或写入第四个状态键。
- 所有时间以服务端时间戳和状态键为准；客户端只能展示相对时间和刷新后的权威结果，不自行判定 36/72 小时阈值。

## 4. 统一页面状态

| 状态            | 表现                                                       | 可执行操作             |
| --------------- | ---------------------------------------------------------- | ---------------------- |
| 初始加载        | 骨架屏保留页面结构；状态区显示“正在同步 Momo 的近况”       | 无，避免误提交         |
| 无宠物          | 明确说明“还没有 Momo”；不出现照料按钮或虚构时间线          | 去领养                 |
| 未登录/会话失效 | 保留只读说明，说明需登录才能保存学习与陪伴记录             | 登录/重新授权          |
| 提交中          | 原按钮禁用、文案改为“正在确认”，保留幂等上下文             | 查询上次结果（超时时） |
| 成功            | 显示权威积分/状态/时间与账本或时间线入口；再出现一次短反馈 | 查看记录/返回今日      |
| 配额耗尽        | 显示服务端给出的本地日恢复时间，不提供绕过入口             | 查看错词/返回今日      |
| 网络失败        | 保留已知状态、错误原因与“重试/查询上次结果”                | 重试、查询结果         |
| 受限/失败       | 说明未登录、状态已变化或请求重复等原因，不暴露内部错误     | 合理的下一步           |
| 媒体不可用      | 静态 Momo 场景与文字反馈保持可用                           | 关闭声音/重试媒体      |

所有业务写操作均须防止重复点按。成功动画绝不能代替状态、积分回执、错误信息或下一步说明。

## 5. 无障碍要求

- 所有状态同时提供文字、图标和颜色；正文与背景对比度至少达到 WCAG AA。
- 页面切换后，焦点移动至新页面的 `h1`；当前主导航项使用 `aria-current="page"`。
- 背词弹窗需具备 `role="dialog"`、可访问名称、焦点进入、焦点圈定、`Esc` 关闭和关闭后焦点恢复。
- 进度使用带名称的 `role="progressbar"`，例如“本组学习进度，第 4 题，共 10 题”。
- 对用户主动操作的学习、互动和重逢结果使用 `role="status"` 或 `aria-live="polite"`；自然叫声文字和待机文案不得持续使用实时播报，避免每隔一段时间打断读屏。
- 每个写操作通过 `aria-describedby` 说明“免费、不扣积分、正在确认”或相关限制。
- 提供应用内“减少动态效果”开关，并尊重系统 `prefers-reduced-motion`；关闭动态后保留场景、状态和文字反馈。
- 声音开关必须表达开/关状态、可键盘操作并保存偏好。首次欢迎页提前告知会偶尔出现轻声，用户无需点击宠物才能触发自然陪伴声。

## 6. 媒体与性能要求

- 首屏只加载 Momo 的静态场景和最小必要 UI；不加载狗狗、动态视频、商城或未开放内容资源。
- 首屏场景应提供尺寸信息、占位/低清预览与失败回退，防止白屏或布局跳动。
- 猫咪声音在真正需要播放前按需加载；不使用 `preload="auto"` 预载概念宠物的音频。
- 自动叫声只在应用前台、声音开启且满足平台自动播放策略时尝试播放；恢复前台也必须遵守至少 45 秒的冷却时间。
- 声音、图片和未来视频失败时，退化为静态场景及文字反馈，学习、照料与重逢仍可完成。
- 动态视频不是 Beta 功能。后续视频接入前必须具备来源/授权、时长、分辨率、码率、分包或流媒体预算、弱网和真机验证方案。
- 媒体不得阻塞状态刷新和核心操作；H5 应持续测量首屏资源并遵守项目性能预算。

## 7. 推荐语义选择器

前端测试优先使用可见的语义名称，不依赖样式类、像素位置或易变文本。

```ts
getByRole('navigation', { name: '主导航' })
getByRole('button', { name: '开始背词' })
getByRole('progressbar', { name: '本组学习进度' })
getByRole('dialog', { name: /背单词/ })
getByRole('button', { name: '确认重逢' })
getByRole('status', { name: '学习结果' })
getByRole('heading', { name: '照料 Momo' })
getByRole('button', { name: '关闭陪伴提醒' })
```

仅对不可稳定通过语义定位的动态区域使用以下 `data-testid`：

```text
authoritative-learning-receipt
care-state-banner
care-event-timeline
research-feedback-card
```

## 8. 前端验收清单

- [ ] 新用户可完成安心说明、登录、命名和领养，不会看到伪造积分或宠物历史。
- [ ] Beta 主导航仅包含“今日 / 学习 / Momo / 我的”。
- [ ] `normal`（正常陪伴）、`reminder`（温和提醒）和 `resting`（休养）均有独立、可理解的页面状态与唯一主操作；重逢仅作为客户端提交中的瞬态 UI，不创建服务端第四状态。
- [ ] 任意一项基础互动都免费，在 `normal` / `reminder` 下可完成陪伴互动且不要求当天完成其他互动；`resting` 只能通过专用免费重逢恢复。
- [ ] 只有完成 10 题且正确率达到 80% 的服务端确认结果才显示 `+8 分` 回执。
- [ ] 低于 80%、每日配额耗尽、重复提交、会话失效、离线和超时重试均有可读界面。
- [ ] 页面具备加载、空、错误、成功、禁用和媒体降级状态；已确认操作不会被静默丢弃。
- [ ] 键盘可完成导航、学习、互动、静音、减少动态效果、关闭提醒和关闭弹窗。
- [ ] 自动化 UI 测试覆盖领养 → 学习成功/失败 → 免费互动 → 休养 → 重逢，以及焦点管理、媒体降级与网络失败。
