## 2. 产品概述

### 2.1 产品愿景

英语养宠计划是一款把可验证英语学习与治愈型虚拟宠物陪伴结合的应用：用户完成短而有效的学习获得成长积分，并记录宠物互动和学习反馈。房间、更多互动与个性化学习反馈在首轮 Beta 验证通过后再评审。宠物不是施压工具，而是记录并回应用户成长的伙伴。

产品不把学习包装成可无限领取的游戏奖励。积分、可解锁内容、陪伴状态和后续排行榜均由服务端裁决，客户端仅负责引导、展示和提交操作。基础照料不以积分、付费或限时失败为门槛；它应让用户感到被欢迎，而非害怕失去。

### 2.2 北极星行为

```text
完成学习 → 获得可追溯积分 → 解锁/记录陪伴反馈 → 宠物稳定陪伴 → 看见英语与关系成长 → 继续学习
```

### 2.3 成功标准

MVP 以“单只宠物的学习—陪伴闭环”为成功标准：用户完成一次合规学习后只能得到一次奖励，能获得可信、温和且有记忆点的宠物反馈，并理解自己可随时回归，不会因暂时离开而失去宠物。

首轮 Beta 重点观察：

- 首次领养完成率、首次学习完成率、首次互动完成率。
- 次日/七日留存、学习任务完成率，以及首周完成至少三次学习的用户比例。
- 用户是否感到宠物有陪伴感、是否愿意继续使用、是否愿意为非数值性内容付费；这些指标只用于改善体验，不用于制造焦虑或诱导消费。
- 重复领奖、权益重复发放、状态结算错误等 P0 一致性问题必须为零。

### 2.4 首轮用户验证设计

- 招募 20–30 名年满 18 周岁的目标用户，进行为期 14 天的封闭测试；测试前明确说明是未公开测试、可随时退出，收集最少必要的行为数据与访谈反馈。
- 完成入组是指成功创建会话、领养 Momo 并抵达今日页；研究同意是独立、默认不勾选的选择，不影响入组或任何基础功能。首周为 `enrolled_at` 起的 168 小时；D1/D7 分别记录入组后 24–48 小时、144–192 小时内是否有服务端确认的学习。
- 首周关键行为是“完成至少三次合规学习”，而非在线时长、连续打开或付费金额；每次学习后可收集一次可跳过的宠物反馈评价。
- 内部试验信号（不是统计显著性结论）：至少 60% 的完成入组用户在首周完成三次学习；至少 10 名自愿访谈用户中一半对“宠物陪伴感”给出 4/5 或以上；至少六名用户能说清楚愿意为哪类装扮、互动或学习计划付费及原因。
- 不在此轮真实收款。付费意愿采用内容卡片、价格区间和访谈验证，避免把小样本、好奇点击或救助焦虑误判为商业需求。
- 仅在 P0 闭环、数据与内容授权、测试门槛均满足，且生产依赖审计的 critical/high 为零时，才可邀请外部测试者；不满足时只允许内部演示和回归验证。

## 3. 目标用户与场景

| 用户                                    | 目标                         | 主要阻碍                         | 产品回应                                             |
| --------------------------------------- | ---------------------------- | -------------------------------- | ---------------------------------------------------- |
| 18–30 岁的学生/职场新人，想建立英语习惯 | 每天有明确、可完成的学习理由 | 任务缺乏即时反馈，容易中断       | 用短学习单元换取可见、温和的陪伴反馈，并展示完成回执 |
| 暂时无法养猫狗、但喜欢陪伴感的成年人    | 低负担地获得真实感陪伴       | 害怕复杂规则、突然惩罚或情绪绑架 | 宠物可暂时休养、随时重逢；提醒可关、无不可逆损失     |
| 重视成长与成就感的持续学习者            | 看见长期进步                 | 数据分散、激励单一               | 提供学习记录、宠物记忆、个人周报和可选成长内容       |

首轮 Beta 不面向未成年人、需要医疗建议、真实宠物诊断或真实世界宠物用品交易的用户。未成年人范围、监护人同意与语音处理方案在未来扩展前另行评估。

## 4. 范围、非目标与产品原则

### 4.1 MVP 范围（首轮 Beta，M1–M2，P0）

1. 账户、会话、资料与入组时确认的时区。
2. 一个可验证的背单词学习单元：10 词一组、正确率至少 80%、完成回执和每日额度。阅读与口语不作为首轮 Beta 的发布前置条件。
3. 不可变积分账本、每日额度、连续学习和任务完成回执。
4. 一只默认猫咪（原型名为 Momo）的领养、命名、陪伴档案与基础互动；犬类和多宠物在验证后排期。
5. 免费的基础照料互动（喂食、补水、整理），以及可恢复的“正常—提醒—休养—重逢”状态。
6. 今日、学习、Momo、我的四个页面；静音/减少动态效果与可解释错误。
7. 20–30 人封闭测试所需的最小化埋点、反馈与退出机制。

### 4.2 后续范围（M3+）

- 阅读、口语、犬类、多宠物、成长阶段和个人周报。
- 可选陪伴商店：外观、房间、互动动作、声音主题与个性化学习计划。
- 房间装饰、成就、挑战、更多宠物内容和公开排行榜。
- 宠物走、跑、跳、躺等高质量动态视频；仅在沉浸感与留存假设成立后，按授权、性能预算和平台能力接入。

### 4.3 明确非目标

- 好友、聊天、礼物、交易市场、真实宠物医疗或物品交易。
- 通过动画、广告、分享或纯点击取得积分。
- 客户端本地时间、客户端余额或客户端状态机作为最终业务事实。
- 宠物永久死亡、疾病治疗倒计时、药品、救助道具、付费复活，或以离开应用为代价的任何不可逆损失。
- 在首轮 Beta 收费、抽卡/盲盒、强制广告或以焦虑驱动的限时购买。

### 4.4 产品原则

- **学习可验证**：奖励只在服务端确认任务完成后发放。
- **学习先有效**：每个学习单元有明确目标、完成条件与结果反馈；宠物增强动机，不能掩盖低质量学习内容。
- **陪伴可恢复**：离开后宠物进入休养，暂停成长解锁但不消失、不扣除权益；用户回归时有温和、低成本的重逢路径。
- **规则可解释**：每项状态都展示原因、发生/截止时间和可做的下一步。
- **低压默认**：提醒、连续学习与排行榜可关；不因缺席羞辱用户，不把宠物痛苦、死亡或资源短缺用作留存手段。
- **事实可追溯**：积分、权益与照料状态变化均可追溯到事件、时间和规则版本。
- **商业化不伤害关系**：付费只扩展表达、内容或效率，不能购买学习结果、排名优势、基础照料资格或从惩罚中脱身。

## 5. 信息架构与核心路径

### 5.1 一级页面

| 页面 | 用户要完成的事           | 主要内容                                               |
| ---- | ------------------------ | ------------------------------------------------------ |
| 今日 | 选择一件最有价值的下一步 | 宠物陪伴、短学习入口、学习额度、积分与行动入口         |
| 学习 | 完成一个可验证的英语任务 | 词组入口、10 题过程、纠错、提交、结果与积分回执        |
| Momo | 任选一项轻量互动或重逢   | 宠物状态、免费互动、唯一重逢入口、状态时间线           |
| 我的 | 查看记录和体验设置       | 学习记录、积分账本、连续天数、提醒、声音、减少动态效果 |

### 5.2 首次闭环

```text
欢迎与安心说明 → 授权/登录 → 命名并领养 Momo → 今日
→ 选择一组背词 → 完成 10 题、查看纠错与成绩 → 服务端发放积分与陪伴反馈
→ 任选一次免费基础互动 → 今日记录学习与陪伴记忆
```

### 5.3 风险闭环

```text
服务端结算到提醒/休养 → 今日与 Momo 页说明离开时长和温和下一步
→ 提醒中任选一次基础互动；休养中仅完成一次免费重逢
→ 服务端原子校验并写入事件 → 客户端刷新为权威状态；学习不影响恢复资格，不扣除积分、不要求购买、不产生永久损失
```

## 6. 功能需求与验收标准

### FR-01 账户、会话与资料（P0）

**需求**

- 支持微信登录及后续可扩展的登录方式；首次使用必须完成会话创建。
- 用户可设置昵称、头像、学习目标、提醒偏好和 IANA 时区；默认时区仅作为建议，服务端在入组时保存最终选择。首轮 Beta 不提供时区修改入口。
- 提供退出登录、会话失效提示、重新授权和账户数据导出/删除入口。
- 未登录用户可以阅读产品规则和原型式展示，但不能提交学习、解锁或照料操作。

**验收**

- 受保护接口在缺少、过期或伪造会话时返回明确的未授权错误，前端给出重新登录入口。
- 服务端基于入组时冻结的 IANA 时区裁决每日额度；账本和学习事件保留 UTC 时间与当时的本地日键，客户端不能以改本机时间绕过额度。
- 删除与导出请求有明确确认、进度和完成/失败状态；不在客户端展示敏感服务端诊断信息。

### FR-02 领养与宠物档案（P0）

**需求**

- 首次领养前明确说明：宠物会根据真实时间进入提醒或休养，但不会因用户离开而消失；学习积分来自可验证任务，基础照料不收费、不消耗积分。
- 首轮 Beta 领养默认猫咪（原型名为 Momo），用户可命名；品种、犬类和第二只宠物必须在首轮验证通过后再开放。
- 每个 Beta 账户仅一只活跃宠物；后续上限与多宠物规则应在不引入压力、刷榜优势或内容负担前重新评审。
- 宠物档案展示名称、物种、领养时间、当前陪伴状态、最近学习/互动记忆和下一项可选互动。
- 用户离开时保留完整关系、成长与解锁内容；宠物进入休养期间只暂停新的成长反馈，回归后可恢复。

**验收**

- 领养重复提交只创建一只宠物；服务端按用户和幂等键去重。
- Beta 中重复领养请求返回已有宠物，不创建额外宠物或扣除积分。
- 从休养回归只需完成明确的重逢互动；任何客户端都不能直接篡改状态、成长或积分，且回归不产生额外收费。

### FR-03 学习任务与完成判定（P0）

| 类型     | 首轮 Beta | 最小完成条件              | 单次积分 | 每日上限 |
| -------- | --------- | ------------------------- | -------: | -------: |
| 背单词   | 是        | 10 词一组，正确率至少 80% |        8 |     3 次 |
| 英语阅读 | 否        | 完成文章阅读与理解题      |       20 |     2 次 |
| 口语练习 | 否        | 完成场景表达与复盘        |       35 |     2 次 |

**需求**

- 学习页在首轮只展示背单词的剩余额度、奖励、预计耗时与不可用原因；阅读与口语用“待验证后开放”呈现，不制造无法完成的任务入口。
- 背单词提供词卡、答案提交、正确率、纠错提示和结果页。阅读与口语的内容版权、转写/评估能力及数据处理在后续单独评审。
- 首轮词库按明确的学习目标和难度范围组织，并记录首次作答与至少一次延迟复习（间隔不少于一个用户本地日）的正确率；这用于判断内容与反馈是否有效，不在样本不足时对外宣传学习效果。
- 每次提交携带会话标识和幂等键；服务端验证任务内容、完成条件、每日额度与用户归属后，再生成积分账本事件。
- 网络中断、重复点击、返回页面或跨设备重复提交都不重复发奖。客户端对“提交中”“已确认”“需重试”有明确状态。

**验收**

- 背单词正确率低于 80% 不发放积分，并显示可重试的解释。
- 同一会话重复提交只产生一条奖励账本事件与一次可读回执。
- 达到每日上限后，任务入口展示次日恢复时间（以服务端时区规则计算），不能通过改本机时间绕过。
- 研究记录能够区分首次与延迟复习表现；用户可选择不参与研究反馈，且该选择不影响正常学习或积分。

### FR-04 积分与连续学习（P0）

**需求**

- 积分余额由不可变 `point_ledger` 聚合，记录来源、数量、任务/订单引用、事件时间、幂等键和规则版本。
- 首页和学习页展示可用积分、今日已获积分、每种任务剩余额度；“余额”不由客户端自行累加作为事实。
- 支持每日打卡与连续学习天数；连续规则、时区和中断规则在服务端统一处理。
- 用户可在“我的”中按时间查看积分变动及对应来源。

**验收**

- 余额永不小于零；后续兑换失败、重复请求和事务异常不会产生扣减。
- 每一笔积分变动可定位到发起请求、业务事件和规则版本，面向用户的列表不暴露内部 ID 或敏感诊断。
- 并发消费余额时，只有满足余额的操作成功，所有结果可复核。

### FR-05 陪伴商店与商业化边界（M3，P1）

首轮 Beta 不提供真实收款，也不要求用户购买任何资源。验证通过后，可按下列边界设计可选陪伴内容：

| 内容类别   | 示例                               | 可否影响学习/基础照料    | 首轮 Beta 验证方式     |
| ---------- | ---------------------------------- | ------------------------ | ---------------------- |
| 外观与空间 | 房间主题、项圈、玩具陈列           | 不可                     | 内容卡片与访谈         |
| 互动与声音 | 走、跑、跳、躺等动作片段、声音主题 | 不可                     | 偏好排序与性能测试     |
| 学习效率   | 个性化学习计划、复习提醒、学习回顾 | 只改善建议，不可直接给分 | 功能原型与价格区间访谈 |

**需求**

- 所有付费内容均为可选内容或效率服务，价格、续费方式、可用范围和退款/取消入口必须在购买前清晰展示。
- 不出售基础照料资格、恢复休养的资格、积分、学习完成记录、排行榜分数、救助道具或任何规避负面状态的内容。
- 不采用抽卡/盲盒、强制广告、倒计时恐惧文案或以宠物痛苦催促购买；不把真实货币与不可逆关系损失绑定。
- 如实现积分兑换，服务端以不可变账本记录兑换与权益；客户端只展示最终权益，不能伪造解锁状态。
- 动态视频、音频和装扮必须有可核验的授权、来源和下架策略；首次加载按需进行，失败时退化为静态图与文字反馈。

**验收**

- 关闭付费入口或不购买任何内容时，用户仍能完成全部基础学习和照料闭环，宠物不会进入不可恢复状态。
- 同一订单/兑换幂等键只产生一条账本事件与一项权益；余额不足、下架、重复提交或事务失败不扣减、不发放。
- 任何购买页都不含误导性默认勾选、隐藏价格或以宠物损失威胁用户的文案。

### FR-06 基础照料、真实时间与可恢复状态机（P0）

**需求**

- 照料页列出每只活跃宠物的喂食、补水、整理等基础互动，显示上次互动时间、下一项推荐互动和可执行操作。基础互动不消耗库存、不要求积分或付费。
- 时间以服务端生成的时间戳为准。定时任务与用户打开应用时的补结算都必须安全重试、可重复执行且不会重复扣减或重复结算。
- 事件时间线展示状态改变的原因、时间、影响与重逢方式；客户端本地倒计时仅用于展示，刷新后必须与服务端重新同步。

**规则**

| 状态     | 触发条件                       | 用户看到的反馈                                               | 可恢复方式               |
| -------- | ------------------------------ | ------------------------------------------------------------ | ------------------------ |
| 正常陪伴 | 距最近一次陪伴事件少于 36 小时 | 宠物正常陪伴，可获得学习后的成长反馈                         | 无需操作                 |
| 温和提醒 | 距最近一次陪伴事件达到 36 小时 | 轻提示“有空回来看看我”；可关闭提醒                           | 完成任一基础互动         |
| 休养     | 距最近一次陪伴事件达到 72 小时 | 宠物在安全的休养空间等待；暂停新的成长解锁，不展示痛苦或责备 | 只可完成一次专用重逢互动 |

领养创建时以 `adopted_at` 作为第一条陪伴事件，用户获得完整的 36 小时安心期。服务端状态枚举仅为 `normal`、`reminder`、`resting`；`reunion` 是只允许在 `resting` 提交的免费、幂等事件，成功后写入新的陪伴事件并切回 `normal`。任意基础互动（喂食、补水或整理）只允许在 `normal` / `reminder` 中提交，并写入新的陪伴事件；它们是表达方式而非每日待办。学习不改变陪伴状态，也不作为重逢或恢复成长节奏的资格。基础互动与重逢不消耗积分、库存或付费权益。状态机不得出现疾病、治疗窗口、资源耗尽、死亡或其他不可逆结果；阈值、文案与提醒频率均须配置化并经 Beta 验证。

**验收**

- 喂食、补水、整理和重逢均验证登录用户对宠物的归属、当前状态与幂等键；重复提交返回首次结果，不生成重复互动事件或重复成长反馈。休养状态下的基础互动、非休养状态下的重逢均返回可读的状态不匹配结果。
- 离线、重复请求、状态已变化或当前状态不允许时，接口返回可读结果且不篡改学习积分或后续权益。
- 对每个阈值、时区边界、重复结算和并发操作有可控时钟的单元测试；用户端可看见失败原因和温和的下一步。

### FR-07 首页、提醒与状态反馈（P0）

**需求**

- 首页按风险优先级展示“现在最需要做的事”，而不是只展示装饰性信息。
- 展示活跃宠物摘要、下一到期照料、今日学习额度、可用积分和直接行动入口。
- 加载、空、错误、成功、禁用和离线/重试状态均需覆盖；已确认的学习或照料操作不会因网络中断被静默丢弃。
- M4 提供可配置提醒（陪伴互动、学习计划与连续学习）；提醒默认关闭或采用低频建议，尊重系统权限、静默时段与用户选择。

**验收**

- 提醒与休养状态有文字、图标、可选行动入口和关闭入口；仅用颜色不视为满足要求，也不得暗示宠物会受到伤害。
- 无活跃宠物时引导领养，不展示误导性的照料按钮。
- 接口错误不泄露堆栈、SQL、密钥或内部实现；服务端以关联 ID 记录脱敏诊断。

### FR-08 成长、个人周报与排行榜（M3，P1）

**需求**

- 成长由完成学习、温和互动和持续回归共同构成，展示为亲密度、共同记忆或可解锁场景；不以缺席扣除既有关系，也不因付费直接提高成长数值。
- 首先提供个人周报：学习次数、掌握情况、连续学习、陪伴记忆与下一周建议。该周报不评价用户是否“合格”，可由用户关闭。
- 公开排行榜不是首轮 Beta 功能。若验证后引入，仅可基于可审计学习完成记录，以可退出、默认匿名且不影响宠物关系为前提；照料次数、消费额、宠物数量和付费内容不参与排名。

**验收**

- 重复请求、客户端改值、消费额或宠物数量不能提高成长或排名。
- 个人周报与未来周分可由原始事件和规则版本重算，用户界面能解释数据来源且不暴露他人私密数据。

### FR-09 宠物动态互动、视频与声音反馈（M3，P1）

**需求**

- 首轮 Beta 仅展示 Momo 的静态或低干扰待机场景；真实感房间、狗狗预览和物种差异化互动在 M3 后才可按验证结论进入开发。
- 完成学习、解锁可选内容或确认照料后，展示一次短暂的、与结果一致的互动反馈；动画只强化已由服务端确认的结果，绝不能替代状态、账本或错误说明。
- 陪伴声在应用前台按自然的非固定间隔出现，而非要求用户每次点击触发。首次设置后记住开关；默认节奏为约 45–105 秒，避免规律循环、连续播放或惊吓式音量。用户可随时静音。
- H5 受到浏览器自动播放限制：首次自动播放被系统拦截时，在用户任意一次正常页面交互后恢复后续陪伴节奏；该交互不是“让宠物叫”的操作。微信小程序和后续原生端须按各平台音频策略验证同等体验。
- 真实产品使用本地打包或已取得使用权的音频资源，记录来源、许可、音量和体积预算；不因播放叫声上传麦克风数据、用户行为音频或调用第三方追踪服务。
- 支持系统“减少动态效果”偏好：减少/停止非必要循环动效；应用切至后台、静音模式或用户关闭声音时暂停媒体，但保留文字反馈和状态。
- 走、跑、跳、躺、撒娇等动态视频不是 MVP 阻塞项。只有首轮验证确认沉浸感有助于学习回归后，才建立按物种、动作、情绪和授权来源管理的短片资源库；先使用少量可循环的短片，不能要求连续播放长视频。
- 视频按需加载、暂停与释放；弱网、节省流量、减少动态效果、后台或用户关闭动效时退化为静态场景和文字。不得为了播放视频上传用户相册、麦克风或精确位置。

**验收**

- M3 后若引入猫/狗预览，物种、真实叫声文案和场景必须一致；互动失败或声音不可用时不影响学习、解锁和照料的业务结果。
- 声音控制可被键盘和屏幕阅读器操作，清楚表达当前开/关状态；不播放不可关闭的背景音乐；自然叫声以非固定间隔自动播放。
- 动画与音频资源不阻塞首屏、核心操作或状态刷新，且不会让 H5 包体积超出既定性能预算。
- 视频资源具备可核验授权、时长/分辨率/码率预算和降级方案；在微信小程序与 H5 分别完成真机/浏览器验证后才能发布。

### FR-10 Beta 研究、内容供给与发布决策（P0）

**需求**

- 在开发阅读、口语、犬类、多宠物、动态视频或真实收款前，先完成第 2.4 节定义的 20–30 人封闭测试；产品只收集完成研究所需的匿名化漏斗数据、可选反馈和研究同意记录。
- 测试反馈同时覆盖：学习是否有实际帮助、宠物是否有陪伴感、休养机制是否令人安心、提醒是否打扰、愿意购买何种非数值内容以及不愿购买的原因。
- 内容供给必须先确认词库、例句、音频、图片和视频的版权、更新责任与下架路径；没有明确授权的内容不得进入测试包或收费内容。
- 每轮试验结束输出一页决策记录：假设、样本、结果、已知偏差、是否继续/调整/停止、数值或文案变更和回滚方式。不得用单一留存或点击指标决定继续投入。

**验收**

- 未同意研究的用户仍可使用基础功能，且不会进入可识别的访谈/反馈名单；删除账户时同时删除或不可逆匿名化可识别研究数据。
- 发布下一阶段前，团队能提供本轮行为数据、访谈摘要、内容授权清单和明确的 go/adjust/stop 决策；若未达到内部试验信号，优先修正学习价值或陪伴体验，而不是增加惩罚、通知或付费压力。外部封闭 Beta 同样必须满足第 11.1 节的依赖安全门槛。

## 7. 关键页面状态与交互规范

| 场景      | 必需表现                                       | 禁止行为                         |
| --------- | ---------------------------------------------- | -------------------------------- |
| 加载      | 骨架/进度、避免重复操作                        | 无限转圈或空白页面               |
| 空状态    | 说明原因和下一步，例如“还没有宠物，去领养”     | 用虚假示例冒充用户真实数据       |
| 网络失败  | 保留可见上下文、提供重试和已确认操作的结果查询 | 静默丢弃提交或重复扣减           |
| 提交中    | 禁用同一操作、保留幂等上下文                   | 允许连续点按制造多笔业务请求     |
| 成功      | 展示权威结果、余额/权益/状态变化和账本入口     | 只做动画而不说明实际结果         |
| 受限/失败 | 说明余额、权限、状态或时间窗口原因及可行下一步 | 暴露内部错误详情或将责任归咎用户 |
| 休养      | 文字、图标、离开时长与重逢路径同时出现         | 暗示宠物受伤、消失或责备用户     |

交互控件需具备可访问名称、键盘可操作性、可见焦点和足够颜色对比度。测试优先使用用户可见的语义选择器；只有必要时使用稳定的 `data-testid`。

## 8. 数据、权限与接口契约

### 8.1 领域数据

| 实体                | 责任与关键字段                                |
| ------------------- | --------------------------------------------- |
| `users`             | 账户、时区、昵称、偏好、连续学习              |
| `pets`              | 用户归属、物种/品种、陪伴状态、领养/休养时间  |
| `learning_sessions` | 用户、任务类型、结果、完成时间、任务证据      |
| `point_ledger`      | 变动金额、原因、关联业务 ID、幂等键、规则版本 |
| `entitlements`      | 用户、可选内容、来源、可用范围、订单/兑换引用 |
| `pet_care_events`   | 宠物、互动类型、发生时间、来源、状态结算结果  |
| `weekly_summaries`  | 周起始时间、用户、学习与陪伴摘要、规则版本    |
| `pet_memories`      | 宠物、学习/互动里程碑、展示摘要与发生时间     |
| `research_feedback` | 研究同意、匿名化反馈、版本与采集时间          |

### 8.2 权限边界

- 所有读取与写入按当前认证用户过滤；普通用户不能访问或修改他人宠物、账本、学习记录和权益。
- 管理操作、跨用户读取和批量修正需要独立授权、理由与审计事件。
- 写操作使用服务端生成或验证的幂等键；关键操作在事务中完成。
- 输入在 API 边界用 Pydantic 模型进行模式、长度和语义校验；数据库访问必须参数化。

### 8.3 接口原则

- FastAPI 生成的 OpenAPI 是唯一接口契约；前端类型从契约生成或受版本控制，不复制状态机或积分逻辑。
- 每个接口定义输入、输出、错误码、认证要求与资源归属检查。
- 请求设置超时、取消/去重和显式错误状态；慢任务需可查询状态，不能阻塞界面。
- 接口变更须提供兼容、迁移或弃用计划，并同步更新客户端。

## 9. 非功能需求

### 9.1 安全与隐私

- 不提交密钥、令牌、真实用户数据或生产导出；配置从环境变量/密钥管理服务读取。
- 日志进行脱敏，不写入凭据、原始语音、完整个人资料或内部查询；使用关联 ID 支持定位。
- 语音、文件或第三方回调在接收前校验类型、长度、权限、速率限制、超时和降级策略。
- 上线前提供隐私政策、账户数据导出和删除机制；Beta 仅招募成年人，未成年人使用与语音数据处理须在未来扩展前重新评估。

### 9.2 性能与可靠性

- 核心列表分页/限量，避免 N+1 查询；常用用户过滤、排序和关联建立索引。
- 记录关键路径的查询次数、服务端延迟、错误率、任务失败率与异常积分/权益事件。
- 高频写操作服务端限流并具备幂等性；定时结算和通知使用可重试异步任务。
- H5 入口存在约 301 KiB 的已知性能风险，M1 前须设定预算并持续测量；高风险依赖审计未清零前不得公开发布。动态视频和音频不计入无媒体首屏预算，必须另设分包/流媒体预算与弱网降级测试。

### 9.3 测试与质量门槛

- 服务端领域规则使用 Pytest；前端展示、交互、请求状态和平台适配使用 Vitest + Testing Library。
- 积分账本、权益事务、照料/休养状态机、时区与幂等性为 P0，必须覆盖正常、边界、拒绝和重复路径。
- H5 使用 Playwright 覆盖登录/会话、学习、领奖、基础照料、休养后重逢、状态变化及关键失败路径；微信平台能力以开发者工具和真机补充验证。后续引入商城与视频时，再补充购买、媒体降级和资源授权相关回归。
- 测试不依赖真实网络、真实时间或执行顺序；时间使用可控时钟，随机逻辑使用可注入种子。

## 10. 埋点、监控与运营边界

| 类别 | 事件/指标                                               | 目的                           |
| ---- | ------------------------------------------------------- | ------------------------------ |
| 漏斗 | 开始/完成领养、开始/完成学习、基础互动、重逢            | 识别学习—陪伴闭环的阻塞点      |
| 质量 | 重复提交拒绝、幂等命中、事务失败、状态结算失败          | 发现 P0 一致性风险             |
| 体验 | 次日/七日留存、首周三次学习比例、陪伴感反馈、提醒关闭率 | 改善节奏和解释，不做操纵性推送 |
| 商业 | 可选内容偏好、价格区间反馈、拒绝原因                    | 验证价值，不真实收款           |
| 安全 | 鉴权失败率、限流触发、异常积分/权益模式                 | 识别滥用和故障                 |

埋点遵循最小化采集原则，不记录答案全文、原始录音或不必要的个人信息。指标分析与人工修正操作均需有权限和审计边界。

## 11. 发布验收与风险

### 11.1 MVP 发布门槛

- 从登录、领养、学习、积分、基础照料到休养后重逢的单宠物闭环通过 UnitTest、UITest 与人工微信端验证。
- 积分、权益和照料状态相关写操作都具备服务端鉴权、归属校验、事务、幂等键和可读审计。
- 高风险依赖审计的 critical/high 为零；当前基线仅用于防止恶化，不能视为发布通过。
- 关键页面支持加载、空、错误、重试和无障碍交互；网络异常不丢失已确认操作。
- 隐私政策、反馈入口、故障通知与数据恢复流程均已就绪。

### 11.2 开放决策

| 决策           | 需要确认                                            | 最晚时间    |
| -------------- | --------------------------------------------------- | ----------- |

| 规则配置       | 数值配置后台、灰度/回滚流程和规则版本呈现方式       | M2 前       |

## 12. 原型覆盖说明

[交互原型](prototype/index.html)保留为内部探索性演示，使用“猫咪 Momo”的演示账户。它展示了以下可点击路径，但尚未满足首轮 Beta 的 10 题学习、领养和状态机验收，不能作为实现或测试的最终依据：

1. 从今日概览进入学习，模拟完成一组背词并得到一次积分回执。
2. 在陪伴空间预览可选的点心、房间装饰、玩具和声音主题；这些内容均不进入首轮 Beta 主导航或积分兑换流程。
3. 在照料页执行免费基础互动，演示陪伴状态与时间线更新；休养时应以需求基线的专用重逢为准。
4. 切换猫咪/狗狗的治愈陪伴空间；应用前台在约 7 秒后开始尝试播放真实叫声，并以自然的非固定间隔继续播放。猫狗切换仅为视觉概念演示，首轮 Beta 的产品范围以单猫为准。
5. 查看领养档案、积分记录、状态时间线和休养/重逢规则说明。

原型中所有数值只用于展示交互状态；声音素材及来源见 [原型素材说明](prototype/assets/ATTRIBUTION.md)。真实实现必须按本文件第 8–9 节和项目开发规则由服务端校验与落账，并使用经授权、可关闭且不阻塞性能的音频资源。
